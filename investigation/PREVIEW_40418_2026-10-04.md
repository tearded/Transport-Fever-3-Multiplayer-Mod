## The four failed Release signatures

Found with `tpfre q dis`, the caller/callee graph and RTTI references, against
both SHA-pinned private indexes. The remaining 139 signatures are unchanged.
Old RVAs in the candidate's inherited comments refer to Release provenance.

| site | Release RVA | Preview RVA | change | player register |
|---|---|---|---|---|
| ViewCreator player | `0x86712a` | `0x86933a` | RIP-relative RTTI displacement moved; wildcard only its four address bytes | `ebx` |
| Catchment player 1 | `0x8765f5` | `0x878845` | following stack read changed from `rbp-0x70` to `rbp-0x60`; exact splice byte `90` becomes `A0` | `r8d` |
| Catchment player 2 | `0x876f36` | `0x87917c` | helper-call rel32 moved; wildcard only its four address bytes | `ebx` |
| Catchment player 4 | `0x8770fd` | `0x879343` | helper-call rel32 moved; wildcard only its four address bytes | `ebx` |

Catchment player 3 also resolves at `0x879300`, with its existing bytes.
The helper maps from Release `0x8764c0` to Preview `0x878700`; its constructor
lambda caller maps from `0x878400` to `0x87a650`. ViewCreator's containing
function maps from `0x867030` to `0x869240`, reached through the matched caller.
The +`0x20c` player reads and registers are preserved at these splice sites.

**Required native change:** a future Preview `guiplayer::SITES` must use
`48 8B 5D A0 48 8B 53 10` for Catchment player 1. Copying the Release's
`48 8B 5D 90 ...` is invalid, even though the new signature resolves.
No Release native table is silently reused as Preview ABI data here.

## Other native findings: review remains open

The original audit reports 21 changed-body target results and nine unknown
comparisons, including the four missing signatures. Deduplicating targets
and following the missing sites gives 21 containing functions to examine.
They were inspected through the shared Rust disassembler; source-level
symbol normalization was used only to make differences readable, not to
approve ABI or callee equivalence.

- `ModuleBuilder::MousePressed` and `StreetTerminalBuilder::MousePressed`
  read one returned object's byte at `+0xeb` instead of `+0xe7`. The hook's
  command-add sites and the stop tool's busy byte still match, but the object
  and helper contracts need review.
- `StreetBuilder::Step` reads virtual-call slots `+0xc8` and `+0xc0` instead
  of `+0xb8` and `+0xb0`. These are reads from vtable pointers, not proof
  that the tool's own player field moved.
- `RailroadCrossingComp` has a corresponding virtual-slot read change from
  `+0xb0` to `+0xc0`.
- `CatchmentAreaHelper` grows its stack allocation from `0x260` to `0x270`,
  relocates locals and changes register allocation/argument preparation.
  Reviewing four splices does not review its whole function.
- `CGameUI::CreateUI` changes an internal allocation request from `0x630`
  to `0x638`, changes virtual-slot reads and rearranges calls. This allocation
  is inside CreateUI; it is not evidence for CGameUI's own object size.
  The mod's renderer/factory layouts and callbacks still need an ABI review.
- Several changed bodies differ only by source-line constants or symbolic
  addresses in the readable comparison. Addresses were deliberately omitted
  there; callee equivalence has **not** been established by that comparison.
- The unknown StationViewer, CSelector and LayerManagerColorMap comparisons
  contain embedded jump tables in `tpfre q dis`. The audit's linear decoder
  also encounters undecodable data. These results remain unknown; neither
  successful prologues nor skipping tables certifies the control flow.

## Script/API review

There are 47 changed source/API/metadata paths, no added or removed script
paths. Duplicate loose/archive declaration copies are counted separately.
The important integration points were compared to `mod/` and the hook:

- `api.modhub.openPath` and `UserProfile.openUrl` are removed; terms now use
  `api.modhub.openTermsInBrowser`. No direct mod/hook call of either removed
  API was found in this checkout.
- `isConstructionModifiable` becomes `isConstructionModifiableEngine`, with
  a missing-component guard; callers and the station-window state change in
  the game. The mod does not call the old name or replace those modules.
- Company progression now handles an enforced level without existing company
  data and returns zero experience. The mod's `progression.follow` wraps the
  same function and forwards arguments and the original fallback; that
  contract is preserved in the source. Live GUI behavior still needs testing.
- The line-manager HUD switches from an array to an entity-keyed colour map.
  It retains its player ownership filter. The mod has no direct dependency on
  the renamed local fields and does not replace that HUD module.
- Graphics presets move into the graphics helper and gain a platform parameter
  getter. The game owns `main_menu` and settings; the mod replaces only
  `main_page`, not those modules.
- The Preview's `main_page` disables construction of an unused release-notes
  icon. The mod menu was regenerated with the existing anchored generator
  from the private Preview source. Regenerating Release exactly matched the
  previous mod copy first; the generated diff is only these six commented
  lines. Multiplayer cards, top-bar entry and lobby window are preserved.
- Remaining groups cover subvention lightweight cards/notifications, GUI
  guards and display changes, campaign deferred proposal handlers, Russian
  town names and credits, and airport geometry corrections. The mod does not
  replace these sources. Airport/progression changes still require simulation
  and real-game acceptance; source review is not a determinism result.
- Both changed `_content.json` files retain their loose file-name inventories;
  archive entry metadata changes. Raw manifest churn is not 4,845 distinct
  API changes. Relevant extracted contents are already included in the 47-path
  comparison.
